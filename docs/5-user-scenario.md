# MultiChat Web 사용자 시나리오

**버전:** 1.0
**작성일:** 2026-08-09
**관련 문서:** [1-prd.md](./1-prd.md), [2-stack.md](./2-stack.md), [3-wireframe.md](./3-wireframe.md), [4-api.md](./4-api.md)

---

## S-1. 서버 구동 & 패스워드 준비

1. 강사(또는 운영자)가 서버 실행 전 환경변수 `ADMIN_PASSWORD`, `STUDENT_PASSWORD`를 지정하고 `npm start`(또는 `npm run dev`) 실행.
2. `prestart`/`predev` 훅이 먼저 `frontend`를 빌드해 `server/static`에 반영 → 이어서 서버 기동. 두 값을 메모리에 로드, 이후 모든 로그인 요청을 이 값과 직접 비교(파일/DB 저장 없음).
3. 브라우저로 접속하면 앱 내 초기 설정 화면 없이 바로 S1(진입 화면)이 뜸.

## S-2. 강사 로그인 & 입장

1. S1에서 강사 카드에 관리자 패스워드 입력, "입장하기".
2. `POST /api/login/admin` → 성공 시 JWT 발급, `sessionStorage`에 저장.
3. WebSocket `ws://.../ws?token=<JWT>` 연결 → 서버가 강사를 접속자 Map에 등록, `welcome` 수신.
4. S2(관리자 채팅 화면) 진입. 좌측 접속자 목록은 아직 강사 본인만 표시.

## S-3. 수강생 로그인 & 입장(정상)

1. S1에서 수강생 카드에 닉네임 "홍길동", 고유식별자 "s01", 공통 패스워드 입력, "입장하기".
2. `POST /api/login/student` → 서버가 패스워드 검증 + 식별자 중복 없음 확인 → JWT 발급.
3. WebSocket 연결 → 서버가 접속자 Map에 등록 → **강사 화면에만** `system`(join) + `user_list` 갱신 브로드캐스트. 홍길동 화면엔 아무 시스템 메시지도 안 뜸(PRD 6항).
4. S3(수강생 채팅 화면) 진입. 좌측 패널엔 공유 파일 목록(`GET /api/share/files`) 표시.

## S-4. 수강생 로그인 — 고유식별자 충돌

1. 다른 수강생이 이미 "s01"로 접속 중인 상태에서 새 사용자가 동일 식별자 "s01"로 입력, "입장하기".
2. `POST /api/login/student` → 서버 응답 409 `IDENTIFIER_TAKEN`.
3. S1 화면 전환 없이 식별자 입력창 아래 인라인 에러 표시, 포커스 이동 → 사용자가 "s01-2" 등으로 재입력 후 재시도.

## S-5. 강사 — 공유 디렉토리 지정

1. 강사가 S2에서 "공유 폴더 지정" 클릭 → S4 모달.
2. 서버 경로 `/srv/course/day1` 입력, "지정하기".
3. `POST /api/share/dir` → 경로 유효성 검증(존재하는 디렉토리인지) 통과 시 서버가 지정 경로 기억.
4. 서버가 전체 접속자에 WebSocket `share_updated` 브로드캐스트 → 모든 수강생 화면이 `GET /api/share/files` 재조회, 좌측 파일 목록 갱신.

## S-6. 수강생 — 파일 다운로드(하위 폴더 포함)

1. 수강생이 S3 좌측 파일 트리에서 `chapter1/index.html` 항목 확인(하위 폴더도 트리로 펼쳐짐).
2. 다운로드 클릭 → `GET /api/share/download?path=chapter1/index.html`.
3. 서버가 지정 루트 하위 경로인지 검증 후 스트리밍 응답 → 브라우저 다운로드.
4. (탈출 시도) `path=../../etc/passwd` 같은 요청은 서버가 400 `INVALID_PATH`로 거부.

## S-7. 강사 → 전체 브로드캐스트 메시지

1. 강사가 S2 "받는 사람"에서 "전체" 선택, 메시지 입력 후 전송.
2. WebSocket `message`(msgType:text, to:"all") 전송 → 서버가 날짜별 `.jsonl`에 append 저장 후 접속 중인 전원(강사 포함)에게 `message` 브로드캐스트.
3. 모든 수강생 화면 대화창에 즉시 표시.

## S-8. 강사 → 특정 수강생 1:1 메시지

1. 강사가 접속자 목록에서 "홍길동" 선택 후 메시지 전송(to:"s01").
2. 서버가 저장 후 강사 본인 + identifier "s01" 소켓에만 `message` 전달.
3. 다른 수강생 화면엔 노출 안 됨.

## S-8-A. 수강생 → 전체 사용자 / 강사 선택 전송

1. 수강생이 S3 좌측 "받는 사람"에서 "전체 사용자"(기본값) 또는 "강사" 선택.
2. "전체 사용자" 선택 시 WebSocket `message`(to:"all") 전송 → 강사 포함 접속 중인 모두에게 브로드캐스트, 다른 수강생 화면에도 표시.
3. "강사" 선택 시 WebSocket `message`(to:"admin") 전송 → 강사와 본인 화면에만 표시, 다른 수강생은 못 봄.
4. 수강생이 `to`에 다른 학생 identifier를 직접 넣어 보내도 서버가 "admin"으로 강제 — 학생 간 1:1은 불가.

## S-9. 클립보드 이미지 붙여넣기 전송

1. 사용자가 스크린샷을 클립보드에 복사한 뒤 대화 입력창에 `Ctrl+V`.
2. 프론트가 `ClipboardEvent.clipboardData.items`에서 이미지 감지 → base64 인코딩 후 WebSocket `message`(msgType:image) 전송.
3. 서버가 `data/messages/images/<date>/<uuid>.png`로 저장, 로그엔 경로만 기록 → 수신자에게 이미지 메시지 브로드캐스트, 대화창에 썸네일 표시.

## S-10. 파일 드래그앤드롭 전송

1. 사용자가 탐색기에서 파일을 대화 입력창 위로 드래그 → 입력창에 점선 하이라이트 오버레이 표시.
2. 드롭 → WebSocket `message`(msgType:file, fileData, fileName) 전송.
3. 서버 저장/브로드캐스트 흐름은 S-9와 동일, 대화창엔 파일명 + 다운로드 링크로 표시.

## S-11. 메시지 우클릭 복사

1. 사용자가 대화창의 특정 텍스트 메시지 위에서 마우스 우클릭.
2. 브라우저 기본 컨텍스트 메뉴 대신 커스텀 메뉴("복사하기") 표시.
3. 클릭 시 `navigator.clipboard.writeText(원문)` → 메뉴 닫힘. 바깥 클릭해도 메뉴 닫힘.

## S-12. 날짜별 대화 조회

1. 사용자가 상단바 날짜 드롭다운 클릭 → `GET /api/messages/dates` 결과로 채워진 목록 표시.
2. "2026-08-08" 선택 → `GET /api/messages?date=2026-08-08` 호출, 대화창을 해당 날짜 메시지로 교체.
3. 수강생 조회 시 시스템 메시지(입퇴장)와 본인 무관 1:1 메시지는 응답에서 제외된 상태로 옴.
4. 각 메시지 시각은 서버가 보관한 UTC 값을 브라우저가 접속자의 로컬 타임존으로 변환해 표시(예: UTC 01:49 → 한국 시간 10:49).

## S-13. 대화 Markdown 다운로드

1. 사용자가 날짜 선택 후 "MD 다운로드" 클릭.
2. `GET /api/messages/export?date=2026-08-08` → 서버가 해당 날짜 로그를 읽어 Markdown 변환(이미지는 `images/<date>/` 상대경로 링크 포함) 후 `.md` 파일로 응답.
3. 브라우저가 `2026-08-08.md` 다운로드.

## S-14. 접속 종료(퇴장)

1. 수강생이 탭을 닫거나 새로고침 → WebSocket 연결 끊김 감지.
2. 서버가 세션 Map에서 제거 → **강사 화면에만** `system`(leave) + `user_list` 갱신 브로드캐스트.
3. 같은 식별자로 재접속 시(S-3과 동일 플로우) 정상 재입장 가능(직전 접속자가 사라졌으므로 충돌 없음).

## S-15. 토큰 만료/서버 재기동

1. 서버가 재기동되면 JWT 서명 시크릿이 새로 생성되어 기존에 발급된 토큰이 전부 무효화됨.
2. 재기동 후 남아있던 클라이언트가 REST 요청 시 401 `INVALID_TOKEN`, WebSocket은 close(4401) 수신.
3. 클라이언트는 자동으로 S1 로그인 화면으로 리다이렉트, 사용자는 재로그인.

## S-16. 본인 메시지 삭제

1. 사용자가 본인이 보낸 메시지를 우클릭 → 컨텍스트 메뉴에 "삭제하기"(빨간 글자) 표시.
2. 클릭 시 WebSocket `delete`(id, date) 전송.
3. 서버가 발신자 본인 것인지 확인 후 해당 날짜 로그에서 제거(첨부파일 있으면 같이 삭제) → 전체 접속자에 `deleted`(id) 브로드캐스트.
4. 그 메시지를 화면에 갖고 있던 모든 사용자(강사·수강생 구분 없이) 화면에서 즉시 사라짐. 갖고 있지 않던 사용자는 아무 변화 없음.
5. (권한 없음) 다른 사람이 보낸 메시지의 id로 `delete`를 보내면 서버가 조용히 무시 — 화면 변화 없음.

## S-17. 이미지 확대보기 & 다운로드

1. 사용자가 대화창의 이미지 썸네일 클릭 → 어두운 배경의 전체화면 오버레이(라이트박스)에 원본 표시.
2. 배경 클릭 또는 우측 상단 ✕ 클릭 → 라이트박스 닫힘.
3. 이미지 썸네일 우클릭 → 컨텍스트 메뉴에 "이미지 다운로드" → 클릭 시 브라우저가 원본 파일명(예: `image.a1b2c3d4.png`)으로 다운로드.

## S-18. 10MB 초과 첨부 시도

1. 사용자가 10MB보다 큰 파일을 드래그앤드롭하거나 클립보드에서 붙여넣기 시도.
2. 클라이언트가 전송 전에 크기 확인 → 초과 시 전송 자체를 막고 입력창 위에 "파일이 너무 큽니다 (최대 10MB, X.XMB)" 인라인 에러 표시.
3. (클라이언트 우회 시 방어) 서버도 base64 디코딩 후 실바이트 크기를 재검증 → 초과 시 `error`(`FILE_TOO_LARGE`) 응답, 저장/브로드캐스트 안 함.

## S-19. 강사 — 수강생 접속 주소 확인

1. 강사가 S2 진입 시 좌측 사이드바 상단에 `GET /api/server-info` 결과로 서버 LAN 주소(예: `http://172.30.1.29:5000`) 표시.
2. 복사 버튼 클릭 → 클립보드에 주소 복사(보안 컨텍스트 아니면 `execCommand` 폴백 사용) → 강사가 수강생들에게 이 주소를 안내.
3. 조회 가능한 주소가 없으면(네트워크 인터페이스 없음 등) "접속 가능한 주소를 찾지 못했습니다" 표시.
